# 基于大语言模型的课程思政案例库信息化平台

本项目面向高校课程思政案例资源建设与教学应用场景，旨在解决案例资源分散、组织方式不统一、检索与复用不便，
以及案例建设流程缺少有效支撑等问题，探索大语言模型技术与课程思政资源建设相结合的可行路径。

平台以课程思政案例为核心数据对象，围绕案例创建与编辑、AI 辅助生成、智能评价、审核发布、分类检索和知识问答等环节，
逐步建立从基础数据维护、案例生产到审核应用的完整业务闭环。同时保留必要的案例版本、审核记录和 AI 调用记录，为内容质量控制、过程追溯和后续功能扩展提供基础。

项目中的大语言模型主要承担内容辅助、知识检索和智能分析等工作，不替代教师及审核人员的专业判断。业务数据、用户权限和审核流程由自研平台统一管理，
MaxKB 作为独立部署的 AI 能力引擎，通过受控的适配层与业务后端进行交互，从而保持业务系统与外部 AI 服务之间清晰、安全且可替换的边界。

本项目为四人本科生创新项目，目前处于持续开发阶段。仓库统一管理前后端代码、基础设施配置、共享契约、数据规范和项目文档，并以可运行、可测试、可维护和便于团队协作为基本工程目标。

## 一、项目目标

项目计划优先打通以下最小业务闭环：

1. 用户登录并根据角色访问相应功能；
2. 管理课程、知识点和思政标签等基础数据；
3. 教师创建、编辑或使用 AI 辅助生成案例；
4. 对案例进行智能评价并保存评价结果；
5. 案例提交审核、退回修改并正式发布；
6. 用户检索和查看已发布案例；
7. 保留必要的案例版本、审核记录和 AI 调用记录。

复杂权限、消息通知、大型数据看板、自动采集、复杂推荐算法和 MaxKB 源码二次开发不作为首版重点。

## 二、总体架构

项目采用“自研业务平台 + 独立 AI 能力引擎”的分层架构：

```text
用户
  ↓
自研前端
  ↓
FastAPI 业务后端
  ├── PostgreSQL 业务数据库
  └── MaxKB 适配器
          ↓
        MaxKB
          ├── 大语言模型
          ├── 知识库
          ├── 向量检索
          └── AI 工作流
```

### 系统边界

- 前端原则上只调用自研业务后端，不直接调用 MaxKB；
- 业务后端负责用户、课程、标签、案例、版本、审核和评价等领域业务；
- MaxKB 负责模型接入、知识库、RAG 检索和 AI 工作流；
- 业务数据库与 MaxKB 运行数据库相互独立；
- MaxKB API Key、模型密钥和数据库密码不得提交到 Git 或下发到浏览器；
- 项目通过适配层调用 MaxKB，不直接依赖其 Django 模型或内部数据库；
- 当前不修改 MaxKB 源码，后续如有必要应单独评估。

## 四、仓库结构

```text
.
├─ backend/          # FastAPI 业务后端与 MaxKB 适配器
├─ frontend/         # 自研前端页面与交互
├─ contracts/        # OpenAPI、JSON Schema、Mock 和接口变更记录
├─ resources/        # 数据规范、标签字典、评价规则和脱敏样例
├─ infra/            # Docker、数据库、Nginx 和部署配置
├─ tests/            # 跨模块契约测试、集成测试和固定评测集
├─ docs/             # 架构、数据库、会议和技术决策文档
├─ .env.example      # 环境变量模板，不包含真实密钥
├─ .gitignore
├─ CONTRIBUTING.md
└─ README.md
```

各目录的详细职责见对应目录内的 `README.md`。

`backend/tests/` 用于后端测试，而根目录`tests/`用于跨模块测试。

## 七、配置与安全

1. 复制 `.env.example` 为本地 `.env` 后再填写真实配置；
2. `.env`、密钥、密码、Token 和本地运行数据不得提交；
3. MaxKB 和模型密钥只能保存在服务端环境中；
4. 示例数据必须脱敏，并确认不存在隐私和版权风险；
5. Docker Volume、数据库文件、上传文件和备份文件不得提交；
6. 发现密钥误提交时，应立即停用并更换密钥，不能只删除 Git 中的文件。

各环境变量的具体用途、当前阶段建议值和自检方法见
[环境变量说明](docs/environment-variables.md)。
