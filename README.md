# 基于大语言模型的课程思政案例库信息化平台

面向课程思政案例建设与使用场景，提供案例数据管理、检索、辅助生成、智能评价、审核发布和知识问答等能力。

本项目为四人本科生创新项目，目前处于 **4B：开发环境与团队协作规范建设阶段**。当前仓库主要用于建立工程结构、协作规则和配置基线，尚未形成可运行的完整系统。

## 一、项目目标

项目计划优先打通以下最小业务闭环：

1. 用户登录并根据角色访问相应功能；
2. 管理课程、知识点和思政标签等基础数据；
3. 教师创建、编辑或使用 AI 辅助生成案例；
4. 对案例进行智能评价并保存评价结果；
5. 案例提交审核、退回修改并正式发布；
6. 用户检索和查看已发布案例；
7. 保留必要的案例版本、审核记录和 AI 调用记录。

复杂权限、消息通知、大型数据看板、自动采集、复杂推荐算法和 MaxKB 源码二次开发不作为首版重点。

## 二、总体架构

项目采用“自研业务平台 + 独立 AI 能力引擎”的分层架构：

```text
用户
  ↓
自研前端
  ↓
FastAPI 业务后端
  ├── PostgreSQL 业务数据库
  └── MaxKB 适配器
          ↓
        MaxKB
          ├── 大语言模型
          ├── 知识库
          ├── 向量检索
          └── AI 工作流
```

### 系统边界

- 前端原则上只调用自研业务后端，不直接调用 MaxKB；
- 业务后端负责用户、课程、标签、案例、版本、审核和评价等领域业务；
- MaxKB 负责模型接入、知识库、RAG 检索和 AI 工作流；
- 业务数据库与 MaxKB 运行数据库相互独立；
- MaxKB API Key、模型密钥和数据库密码不得提交到 Git 或下发到浏览器；
- 项目通过适配层调用 MaxKB，不直接依赖其 Django 模型或内部数据库；
- 当前不修改 MaxKB 源码，后续如有必要应单独评估。

各目录的详细职责见对应目录内的 `README.md`。

## 八、配置与安全

1. 复制 `.env.example` 为本地 `.env` 后再填写真实配置；
2. `.env`、密钥、密码、Token 和本地运行数据不得提交；
3. MaxKB 和模型密钥只能保存在服务端环境中；
4. 示例数据必须脱敏，并确认不存在隐私和版权风险；
5. Docker Volume、数据库文件、上传文件和备份文件不得提交；
6. 发现密钥误提交时，应立即停用并更换密钥，不能只删除 Git 中的文件。

各环境变量的具体用途、当前阶段建议值和自检方法见
[环境变量说明](docs/environment-variables.md)。
