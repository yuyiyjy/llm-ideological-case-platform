3B02 前后端对接约定接口规范文档
项目名称：基于大语言模型的课程思政案例智能库平台适配配套：3B01 前端接口清单，统一遵循 RESTful 接口规范、全局 Token 鉴权、角色权限拦截规则
一、基础通用规范
1. 接口基础规则
基础请求地址前缀统一全局前缀：/api，区分静态页面资源与业务接口地址，所有接口必须携带该前缀。
请求方式固定语义
请求方式
业务语义
适用场景
GET
只读查询，无数据修改
列表查询、详情查询、分类数据、首页统计数据
POST
新增 / 提交 / 触发任务
登录、收藏、AI 生成、案例提交审核、批量导入
PUT
完整更新已有资源
修改个人信息、修改密码、编辑案例、调整用户角色
DELETE
删除资源
取消收藏、删除生成记录、删除平台案例、重置密码外的销毁操作
URL 命名硬性规则
全小写英文，多单词使用横杠-分隔，禁止驼峰、大写字母；
URL 只描述资源名词，动作交由请求方式承载；
管理员专属接口统一增加层级/api/admin/，和普通用户接口做隔离。
2. 三类参数传递规则
路径参数（{id}）适用：资源唯一主键 ID（案例 ID、记录 ID）示例：GET /api/case/detail/{id}，后端通过@PathVariable接收参数；
Query 查询参数（? 拼接）适用：GET 请求筛选条件、分页参数、搜索关键词，拼接在 URL 后方示例：GET /api/case/list?keyword=工匠精神&page=1&size=10；
Body 请求体参数适用：POST/PUT 请求，传递表单、大文本、账号隐私数据、复杂结构体，后端通过@RequestBody接收 JSON 参数。
3. 全局统一返回 JSON 格式
所有接口返回固定结构体，后端统一封装，前端全局解析：
json{  "code": 200,       // 状态码：200成功、401未登录、403权限不足、500服务异常  "msg": "操作提示文案", // 成功/失败提示文字  "data": {}          // 业务返回数据，无返回值时返回null/空对象}
分页接口固定返回 data 结构
json{  "code": 200,  "msg": "查询成功",  "data": {    "total": 100,    // 总数据条数    "records": [],    // 当前页数据数组    "page": 1,        // 当前页码    "size": 10        // 每页条数  }}
4. Token 身份鉴权规范
除登录、退出登录接口外，其余所有接口请求头必须携带鉴权 Token：Authorization: Bearer {后端下发的token字符串}
后端全局拦截校验：
Token 过期 / 缺失：返回code=401，前端跳转登录页；
Token 合法但角色无接口权限：返回code=403，提示无操作权限。
5. 角色权限约束规则
前端仅做页面菜单隐藏控制，后端接口强制二次权限拦截，杜绝前端绕过页面直接调用接口越权操作；
角色权限边界：
学生：仅可访问浏览、收藏、个人信息接口，拦截 AI 生成、案例提交、后台管理全接口；
教师：可访问基础浏览、AI 生成、案例提交、个人拓展接口，拦截管理员后台管理接口；
管理员：开放全量接口权限。

三、前后端协作约定规则
并行开发规则前期后端未完成接口开发时，前端基于本规范编写 Mock 模拟 JSON 数据开发页面；后端接口开发完成后，直接替换真实接口地址联调。
接口变更规则任何接口地址、请求方式、参数、返回字段修改，必须团队前后端同步更新 4B01、4B02 文档，同步告知组员，禁止私自修改接口规则。
异常统一处理后端固定异常状态码含义，前端全局拦截：
401：自动跳转登录页；
403：弹窗提示无权限操作；
500：统一弹窗提示服务异常，请稍后重试。
AI 流式接口专项约定/api/ai/generate采用 SSE 长连接流式返回，前端使用 EventSource 接收分段文本，实现打字机实时展示效果，后端做好超时、异常断开兜底处理。
联调验收标准接口严格匹配本文档约定：地址、请求方式、入参、出参格式完全一致，功能场景符合交互流程文档 4A04，权限拦截生效即为验收通过。
